# Website wording review

Use [the editable Word document](Target-Practice-Website-Wording-Review.docx) to review the latest saved app text, including the 18-hole update. On GitHub, open that file and choose **Download raw** (the download arrow). Open it in Word or import it into Google Docs.

- Write changes in the **Your wording** column; blank means keep the current text.
- Keep the **TP-xxxx** reference numbers.
- Keep `{value 1}` and similar markers wherever calculated scores, distances or other changing values belong.
- Use the global-changes space at the start for changes you want everywhere.
- Return the edited document when ready. You can review one section at a time.

[The readable Markdown version](SITE-TEXT-REVIEW.md) has the same references and can also be edited and returned. Some entries are conditional phrases, accessibility descriptions or older-state labels, so not every entry appears on every screen. This is the latest saved code's wording, which may be ahead of the deployed site until Work applies that update.

`SITE-TEXT-SOURCE-MAP.json` is an implementation reference for applying edits; you do not need to edit it. Generated numbers, decorative symbols and internal code are not wording changes. Account, billing and legal-policy copy will need a separate review when those features are built.

No website text has been changed by creating these documents.

The wording review is intentionally frozen at v17.0 so existing TP references stay stable. The v17.1 My Progress redesign introduces new copy beyond that snapshot; returned edits will be matched to the appropriate current screen.
